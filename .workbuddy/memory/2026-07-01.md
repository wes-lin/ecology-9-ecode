# 2026-07-01

## vscode-ecode tree actions and icons

- Added `businessType` and `parent` to `EcodeNode` so mapped remote nodes keep business classification and direct parent references.
- Moved `RemoteTreeItem` usage to the SDK-exported type and removed the duplicate local tree item type.
- Tree icons now use special icons for folder-like nodes:
  - files: `file`
  - `businessType === 'project'`: `project`
  - `businessType === 'type'`: `symbol-folder`
  - app nodes still show `vm-active` / `vm-outline` by release status
  - other folders keep `folder`
- Implemented eCode app commands that were previously placeholders:
  - `release`
  - `cancelRelease`
  - `setPreload`
  - `cancelPreload`
  - `setPreloadOrder`
- After release/cancel release/set preload order succeeds, the current app node is updated directly and `.ecode/ecode-apps.json` is patched by `appId`.
- After set/cancel preload succeeds, only the current file node state is updated and its direct parent app/folder entry in `.ecode/ecode-apps.json` has `preStateFiles` adjusted.
- These metadata operations intentionally do not update `.ecode/snapshots.json`, because file content does not change.
- Added node-level loading state for these operations. While a command is running, the node icon switches to `sync~spin`; a `finally` block clears loading so failures do not leave nodes stuck.
- Preload state changes now fire tree refresh for the file node itself so the `P` description appears/disappears immediately.
