# TypeScript 迁移与 VS Code 扩展打包

## 工作内容

- 将仓库从 JavaScript 项目配置迁移为 TypeScript 项目配置。
- 新增根级 TypeScript 配置：
  - `tsconfig.base.json`
  - `tsconfig.json`
- 删除旧的 `jsconfig.json`，避免 JS/TS 配置分叉。
- 将 `packages/ecode-sdk` 源码从 `.js` 迁移为 `.ts`。
- 为 `ecode-sdk` 增加 `tsc` 构建输出。
- 将 SDK 包入口更新为 `dist/index.js`，类型声明更新为 `dist/index.d.ts`。
- 更新 SDK 测试，使其基于编译后的 `dist` 输出运行。
- 将 `packages/vscode-ecode` 扩展源码从 `.js` 迁移为 `.ts`。
- 将 VS Code 扩展入口迁移到 `src/extension.ts`。
- 将扩展 provider 代码迁移到 `src/providers`。
- 新增 `packages/vscode-ecode/esbuild.js`，用于打包扩展。
- 配置 esbuild 将 `ecode-sdk` 打进 `dist/extension.js`，同时保持 `vscode` 为 external。
- 更新 `packages/vscode-ecode/package.json`，将 `main` 指向 `./dist/extension.js`。
- 将 `@vscode/vsce` 添加为 `vscode-ecode` 包内开发依赖。
- 新增 `scripts/ensure-releases-dir.js`，在 VSIX 打包前创建 `releases` 输出目录。
- 更新 `.vscodeignore`，让 VSIX 只包含运行所需文件，例如 `package.json`、README、LICENSE、assets 和 `dist/extension.js`。
- 更新 VS Code 调试配置，使 `outFiles` 指向编译后的扩展输出。
- 更新 ESLint 配置以支持 TypeScript。
- 迁移过程中恢复并保留原有中文说明注释。

## 已验证命令

- `pnpm build`
- `pnpm test`
- `pnpm lint`
- `pnpm exec tsc -b`
- `pnpm --filter vscode-ecode package`

## 打包约定

- `vscode-ecode` 通过 esbuild 打包。
- `ecode-sdk` 不作为独立 VSIX runtime dependency 分发，而是打进扩展 bundle。
- monorepo 下使用 `vsce package --no-dependencies` 是有意为之，避免 `vsce` 追踪 pnpm workspace 依赖时扫描到包外路径。
- VSIX 输出目录为 `packages/vscode-ecode/releases`。

**Why:** pnpm workspace 依赖在 `vsce` 打包时容易因为 symlink 和包外路径导致打包失败；bundle 后 VSIX 更独立、更稳定。

**How to apply:** 后续修改扩展运行时代码时，优先保持 esbuild bundle 方案；如果新增 runtime dependency，需要确认它被 bundle 进 `dist/extension.js` 或明确处理 VSIX 分发方式。
