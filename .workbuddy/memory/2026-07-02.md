# 2026-07-02

## vscode-ecode multi-environment support

- Began adding multi-environment support for the VS Code extension.
- Added `ecode.environments` configuration for named environments with:
  - environment name
  - eCode server URL
  - username
  - password
  - local working directory
- Added `ecode.activeEnvironment` and the `ecode.switchEnvironment` command in the `ecodeExplorer` view title area.
- Environment switching uses a VS Code QuickPick and stores the selected active environment in global user settings, not project/workspace settings.
- Removed the legacy flat config compatibility path per preference; the extension now expects environment-based configuration.
- Extracted environment-related types and helpers into `src/config/ecodeEnvironment.ts` instead of putting all logic into `treeDataProvider.ts`.
- Cookie storage is now derived per environment/account using environment name, normalized base URL, and username, so sessions are isolated across environments and accounts.
- Updated provider state handling so switching/refreshing clears the SDK client, tree cache, virtual file content cache, and snapshot store.
- Adjusted local storage layout:
  - downloaded source files go under `localDir/src`
  - metadata goes under `localDir/.ecode/`
  - app config path is `localDir/.ecode/ecode-apps.json`
  - snapshot path is `localDir/.ecode/snapshots.json`
- Started moving app config and snapshot path resolution away from the workspace `.ecode` directory and toward the active environment root.
