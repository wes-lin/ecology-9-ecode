# 2026-07-05

## ecode-sdk request failure handling

- Updated `packages/ecode-sdk/src/client.ts` request handling so JSON responses with `api_status === false` are treated as failed requests.
- Added centralized response failure detection in `_request()` after JSON parsing and logging.
- When the backend returns `api_status: false`, the SDK now throws with the server-provided `msg`.
- Added a fallback error message of `Request failed` when `msg` is missing or unusable.
- This makes SDK callers receive backend business failures as thrown errors instead of silently getting a `Response` that looked transport-successful.

## vscode-ecode tree New / Rename / Delete implementation

- Wired the previously placeholder tree commands in `packages/vscode-ecode/src/providers/treeDataProvider.ts` to real SDK mutations.
- Implemented working handlers for:
  - `createNewApp`
  - `createNewType`
  - `createNewFolder`
  - `createNewFile`
  - `renameItem`
  - `deleteItem`
- Delete now dispatches by node kind:
  - type -> `deleteType()`
  - file -> `deleteFile()`
  - folder/app -> `deleteFolder()`
- Rename now dispatches by node kind:
  - type -> `updateTypeName()`
  - file -> `updateFileName()`
  - folder/app -> `updateFolderName()`
- New actions now dispatch as follows:
  - new app under a type -> `addFolder(name, undefined, typeId)`
  - new type under a type -> `addType(name, parentTypeId)`
  - new folder under a folder/app -> `addFolder(name, parentId)`
  - new js/css/md file under a folder/app -> `addFile(folderId, name, extension)`

## treeDataProvider validation and refresh behavior

- Added shared provider-side helpers for node action handling:
  - required node id validation
  - node kind labeling for clearer UI messages
  - file extension detection
  - name normalization for file/folder/type/app creation and rename
  - structural refresh after successful mutations
- Added name validation in input boxes:
  - disallow empty names
  - disallow `/` and `\`
  - enforce expected file extensions for file create/rename flows
- File rename/create now preserves the intended extension and rejects mismatched extensions.
- Structural mutations now refresh the current container or parent container instead of mutating local tree state in place, reducing stale labels, paths, or children.
- All remote mutations are wrapped with the existing `_withNodeLoading()` pattern so the node shows loading state while the request is in flight.

## sdk follow-up fix

- Updated `packages/ecode-sdk/src/client.ts` so `addType()` returns an awaitable promise like the other SDK mutation methods.
- This allows the VS Code provider to correctly await type creation and surface backend failures from the new `api_status === false` error path.
