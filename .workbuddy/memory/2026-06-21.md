# 项目初始化与 eCode SDK / VS Code 扩展雏形

## 工作内容

- 初始化 `ecology-9-ecode` monorepo 基础架构。
- 根目录 `package.json` 配置 npm workspaces，包含 `packages/*`。
- 创建 `packages/ecode-sdk`：
  - 提供登录、文件树、上传、下载能力。
  - 初始实现为 JavaScript SDK（CommonJS）。
- 创建 `packages/vscode-ecode`：
  - 依赖 `ecode-sdk`。
  - 在 VS Code Explorer 中展示 ecode 目录 / 文件树。
  - 支持下载文件到本地配置目录，默认目录为 `src`。
- 新增 VS Code 扩展配置项：
  - `ecode.baseUrl`
  - `ecode.username`
  - `ecode.password`
  - `ecode.localDir`

## SDK 网络层调整

- 将 `ecode-sdk/src/http-client.js` 从 Node.js 内置 `http` / `https` 模块迁移到全局 `fetch` API。
- 普通 POST body 改为使用 `URLSearchParams` 序列化。
- 上传仍保留 `form-data`。
- 合并 SDK 架构：
  - 将 `http-client.js` 和 `api.js` 的职责并入 `client.js`。
  - 删除 `api.js` 和 `http-client.js`。
  - 对外导出简化为单一 `EcodeClient`。

## VS Code 扩展改进

- `treeDataProvider` 在缺少配置时显示提示节点，便于用户理解为什么树为空。
- 配置错误或登录失败时显示错误信息节点，方便排查。
- 命令标题调整为：
  - `eCode: Refresh Explorer`
  - `eCode: Download File`
- 移除 `vscode-ecode` 的 `activationEvents` 字段。

## 设计约定

- VS Code 1.75+ 会自动根据 `contributes.views` / `commands` 推断激活时机，因此不需要显式维护 `activationEvents`。
- SDK 早期目标是先提供一条可用的登录、树加载、文件操作链路，再逐步整理接口和扩展交互。

## 已验证命令
