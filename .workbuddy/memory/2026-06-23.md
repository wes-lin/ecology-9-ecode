## EcodeClient 自动登录重构

- 重构 `packages/ecode-sdk/src/client.js` 的请求层
- 将原来的 `_request` 拆分为 `_buildFetchOptions` + `_request`
- `_request` 现在具备：
  1. **无 cookie 时自动调用 login()**
  2. **收到会话过期响应（msgcode=-1）时自动重新登录并重试**
- 新增 `_isSessionExpired(resData)` 方法，识别 E9 会话失效信号
- `login()` 改为直接调用 `fetch`，绕过 `_request`，避免递归死循环
- 调用方无需再手动 `isLoggedIn()` + `login()`，直接调用业务方法即可

## ecode-sdk 新增 Logger

- 新增 `packages/ecode-sdk/src/logger.js`，实现 `EcodeLogger` 类
  - 支持级别：`debug / info / warn / error / silent`
  - 支持控制台输出（ANSI 颜色）和文件追加写入
  - 内置 `_redactHeaders` / `_redactBody` 对 cookie/password 等敏感字段脱敏
  - 提供 `logRequest` / `logResponse` / `logSessionExpired` 专用方法
  - 提供 `NOOP_LOGGER` 作为无日志默认值，避免 null 检查
- `EcodeClient` 构造函数新增 `options.logger`，支持三种用法：不传（静默）、传配置对象（自动构造）、传实例
- `index.js` 导出 `EcodeLogger` 和 `NOOP_LOGGER`
- 测试：15/15 全通过

## treeDataProvider remotePath 路径叠加

- 问题：`_mapTree` 中 `remotePath` 只存 `item.name`，子节点不会叠加父级路径
- 修复：`_mapTree` 新增 `parentPath` 参数，`getChildren` 调用时传入 `element.remotePath`
- 拼接逻辑：`parentPath ? parentPath/item.name : item.name`
- 修复后下载文件时 `element.remotePath` 为完整远程路径

## crypto 替换 JSEncrypt

- 移除 `jsencrypt` 依赖，改用 Node 内置 `crypto` 模块
- 失败原因（3 个）：
  1. PEM 格式没有每 64 字符换行
  2. `crypto.publicEncrypt` 默认 OAEP padding，JSEncrypt 用 PKCS#1 v1.5
  3. Key 头部用 `RSA PUBLIC KEY`（PKCS#1），实际应是 `PUBLIC KEY`（SPKI/PKCS#8）
- 修复：新增 `wrapPem()` 处理换行，`rsaEncrypt()` 显式指定 `RSA_PKCS1_PADDING`
- `package.json` 移除 jsencrypt 依赖
- 测试：15/15 全通过

## viewFile 多文件查看修复

- 问题：查看多个文件时只有一个 tab，切换文件会互相覆盖
- 三个根因：
  1. `registration.dispose()` 打开完就销毁 content provider，切回 tab 读不到内容
  2. `preview: true` 预览模式，点新文件替换当前 tab 而非开新 tab
  3. 每次调用都注册新 provider，多文件时互相覆盖
- 修复：
  - 构造函数中注册一次性 `TextDocumentContentProvider`，用 `Map` 缓存所有已查看文件内容
  - `viewFile` 改为往 Map 写入内容后直接打开，`preview: false`
  - 新增 `dispose()` 清理 registration 和 emitter
  - `extension.js` 将 treeDataProvider 加入 `context.subscriptions`

## 面包屑导航（Breadcrumbs）支持

- 问题：自定义 scheme 虚拟文档没有 VSCode 面包屑导航
- 原因：`TextDocumentContentProvider` 太轻量，VSCode 无法理解目录结构
- 修复：新增 `EcodeFileSystemProvider`，实现 `vscode.FileSystemProvider` 接口：
  - `stat()` — 从缓存和树节点判断 File/Directory 类型
  - `readFile()` — 从 `_fileContents` 缓存读取内容
  - `readDirectory()` — 从已加载的树节点收集子项列表
- 构造函数中用 `registerFileSystemProvider('ecode', provider, { isReadonly: true })` 注册
- 移除之前的 `TextDocumentContentProvider` 和 `_onDidChangeContent`
- `viewFile` 直接通过 FS provider 打开文档，VSCode 自动渲染面包屑
