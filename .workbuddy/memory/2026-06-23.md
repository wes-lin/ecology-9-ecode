# SDK 自动登录、日志、加密与虚拟文件系统

## EcodeClient 自动登录重构

- 重构 `packages/ecode-sdk/src/client.js` 的请求层。
- 将原来的 `_request` 拆分为：
  - `_buildFetchOptions`
  - `_request`
- `_request` 新增自动会话处理：
  - 无 cookie 时自动调用 `login()`。
  - 收到会话过期响应（`msgcode=-1`）时自动重新登录并重试。
- 新增 `_isSessionExpired(resData)`，用于识别 E9 会话失效信号。
- `login()` 改为直接调用 `fetch`，绕过 `_request`，避免递归死循环。
- 调用方无需再手动执行 `isLoggedIn()` + `login()`，可以直接调用业务方法。

## ecode-sdk Logger

- 新增 `packages/ecode-sdk/src/logger.js`。
- 实现 `EcodeLogger` 类：
  - 支持级别：`debug` / `info` / `warn` / `error` / `silent`
  - 支持控制台输出，包含 ANSI 颜色
  - 支持文件追加写入
  - 内置 `_redactHeaders` / `_redactBody`，对 cookie、password 等敏感字段脱敏
  - 提供 `logRequest` / `logResponse` / `logSessionExpired` 专用方法
- 新增 `NOOP_LOGGER` 作为默认无日志实现，避免调用方写 null 检查。
- `EcodeClient` 构造函数新增 `options.logger`，支持三种用法：
  - 不传：静默
  - 传配置对象：自动构造 logger
  - 传 logger 实例
- `index.js` 导出 `EcodeLogger` 和 `NOOP_LOGGER`。

## treeDataProvider remotePath 修复

- 修复 `_mapTree()` 中子节点 `remotePath` 不叠加父级路径的问题。
- `_mapTree()` 新增 `parentPath` 参数。
- `getChildren()` 加载子节点时传入 `element.remotePath`。
- 拼接规则：`parentPath ? parentPath/item.name : item.name`。
- 修复后下载文件时 `element.remotePath` 为完整远程路径。

## RSA 加密实现替换

- 移除 `jsencrypt` 依赖。
- 改用 Node 内置 `crypto` 模块。
- 替换原因：
  - PEM 格式需要每 64 字符换行。
  - `crypto.publicEncrypt` 默认 OAEP padding，而 JSEncrypt 使用 PKCS#1 v1.5。
  - Key 头部原来使用 `RSA PUBLIC KEY`（PKCS#1），实际应使用 `PUBLIC KEY`（SPKI / PKCS#8）。
- 新增 `wrapPem()` 处理 PEM 换行。
- 新增 `rsaEncrypt()`，显式指定 `RSA_PKCS1_PADDING`。
- `package.json` 移除 `jsencrypt` 依赖。

## View Remote File 多文件查看修复

- 修复查看多个远程文件时只有一个 tab、文件互相覆盖的问题。
- 根因：
  - 打开后立即 dispose content provider，切回 tab 时读不到内容。
  - `preview: true` 会让新文件替换当前预览 tab。
  - 每次调用都注册新 provider，多文件查看时互相覆盖。
- 修复方式：
  - 构造函数中注册一次性 provider。
  - 使用 `Map` 缓存所有已查看文件内容。
  - `viewFile` 写入 Map 后直接打开。
  - `showTextDocument` 使用 `preview: false`。
  - 新增 `dispose()` 清理 registration 和 emitter。
  - `extension.js` 将 `treeDataProvider` 加入 `context.subscriptions`。

## ecode 虚拟文件系统与面包屑导航

- 为自定义 `ecode:` scheme 增加 VS Code 面包屑导航支持。
- 原因：`TextDocumentContentProvider` 太轻量，VS Code 无法理解目录结构。
- 新增 `EcodeFileSystemProvider`，实现 `vscode.FileSystemProvider`：
  - `stat()`：从缓存和树节点判断 File / Directory 类型。
  - `readFile()`：从 `_fileContents` 缓存读取内容。
  - `readDirectory()`：从已加载的树节点收集子项列表。
- 构造函数中通过 `registerFileSystemProvider('ecode', provider, { isReadonly: true })` 注册。
- 移除之前的 `TextDocumentContentProvider` 和 `_onDidChangeContent`。
- `viewFile` 直接通过 FS provider 打开文档，VS Code 自动渲染面包屑。
